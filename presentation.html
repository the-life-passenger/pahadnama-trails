EXECUTIVE SUMMARY

Project Overview & Problem Statement

Bridging the gap between outdoor enthusiasts and organized Sahyadri trekking.

⚠️ Existing Industry Challenges
  • Manual WhatsApp Chaos: Fragmented bookings through chats cause double bookings and dropped leads.
  • Opaque Pricing & Details: Trekkers struggle to find clear route difficulty, elevation gain, and gear checklists.
  • No Real-Time Seat Counters: Organizers calculate occupancy across spreadsheets without live availability badges.
  • Informal Payment Proof: Manual UPI screenshots lack cryptographic verification and official booking slips.
✨ The Pahadnama Solution
  • Unified Digital Booking: End-to-end direct portal for Maharashtra trails (Harishchandragad, Kalsubai, etc.).
  • Live Slot Inventory: Real-time Saturday/Sunday seat counters (AVAILABLE, FILLING FAST, FULL) with auto-decrement.
  • Dual Checkout Channels: Razorpay Gateway with HMAC-SHA256 signature verification plus 1-click WhatsApp fallback.
  • Executive Operations CMS: Modern obsidian dark control center for routes, media, and security health.

ENGINEERING WORKFLOW

System Design & Request Lifecycle

End-to-end data pipeline between Trekkers, Admin, Server, and Payment Gateway.

Client-Server Architecture with Hybrid SSR Pipeline
1. Initial Page Load (GET /): Server reads active theme from SQLite → Injects data-theme & initial state into HTML → Browser paints Frame 1 with 0ms flicker.
2. Booking Lifecycle: User picks slot → Server creates Razorpay Order → Client completes checkout → Server verifies HMAC-SHA256 → Atomically decrements seat and issues voucher.
3. Admin Management: Admin logs in via /api/admin/login → Server validates scrypt hash → Issues HttpOnly cookie → Authorized CRUD operations on trails & batches.
Architectural Decisions
  • Synchronous SQLite Queries: Avoids connection pooling issues; zero async overhead for local reads.
  • Strict Separation of Concerns: Public APIs separated from privileged admin routes via requireAdmin.
Reliability & Resilience
  • Zero Overwrite Startup: Database check prevents re-seeding default credentials if admin exists.
  • Graceful Fallback: Direct WhatsApp UPI booking activates automatically if online gateway is disabled.
DATA MODELING

Database Schema & Entity Relationships

Relational design normalized for data integrity and high consistency.

1. Catalog Master
  • treks: id (PK), name, slug, difficulty, duration, distance, height, price, cover_photo, document_url, is_featured.
  • trek_dates: id (PK), trek_id (FK), event_date, day_of_week, available_seats, status.
  • photos: id (PK), trek_id (FK), photo_url, caption.
  • faqs: id (PK), trek_id (FK), question, answer.
2. Transactional Records
  • bookings: id (PK), booking_code (UK, e.g. PAHAD-8492), trek_id (FK), slot_date, customer_name, customer_phone, customer_age, participants, total_amount, payment_status, rzp_payment_id.
  • Atomic Decrement: Executed inside an SQL transaction: available_seats = available_seats - N.
3. Governance & CMS
  • admins: id (PK), username (UK), password_hash (salt:hash), created_at.
  • feedback: id (PK), trek_id (FK), customer_name, rating, comment, is_approved.
  • settings: Key-value store for active theme, hero images, opacity, and payment keys.

FINANCIAL INTEGRITY & DEFENSE

Dual Payments & Cryptographic Security

Enterprise-grade financial transactions and server-side defensive protections.

Payment Processing Engine
  • Razorpay Online Checkout: Standard popup supporting Credit/Debit Cards, UPI, NetBanking, and Wallets.
  • HMAC-SHA256 Verification: Server recalculates expected signature; rejects fraudulent client payloads.
  • Sandbox Mode: Test key integration with simulated test cards and live connection verification.
  • WhatsApp UPI Fallback: Coordinators can toggle manual UPI QR payments without gateway commission.
Defensive Security Architecture
  • scrypt Key Derivation: Passwords hashed using memory-hard scrypt with unique 16-byte random salts.
  • timingSafeEqual Verification: Evaluates password hashes in constant time, neutralizing timing attacks.
  • HttpOnly Session Isolation: Shields authentication tokens from client JavaScript, preventing XSS theft.
  • Parameterized Queries: 100% parameter binding completely eliminates SQL Injection vulnerabilities.
